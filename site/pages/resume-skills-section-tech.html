Skills Section on a Tech Resume: What to List and How to Group It

One-line promise

This page shows entry-level and no-experience candidates how to build a tech resume skills section that is believable, ATS-readable, and mapped to real job descriptions.

Who this page is for

This guide is for you if:

  • you are applying for entry-level software, data, or machine learning roles
  • you have little or no formal work experience
  • your skills section is either a giant tool dump or nearly empty
  • you are not sure which skills deserve space on a one-page resume

This page is not for:

  • senior engineers with years of production experience
  • candidates targeting non-technical roles
  • people looking for a generic soft-skills list

Why the skills section matters more when you have no experience

For a candidate with years of work history, the skills section is a quick index. The bullets do the convincing.

For an entry-level candidate, the skills section does three jobs at once:

  • it tells the applicant tracking system (ATS) that your resume matches the job description
  • it gives a recruiter a six-second summary of what you can actually do
  • it sets expectations that your projects and coursework have to back up

That last point is the one most people miss. Every skill you list creates a debt. Somewhere else on the page — a project bullet, a course, a hackathon — you have to pay it off. A skill with no supporting evidence is a red flag, not a strength.

Complete example: an entry-level tech skills section

Here is a full skills section for a fresh graduate targeting entry-level machine learning and data roles:

Skills

  • Languages: Python, SQL, JavaScript
  • Machine learning and data: scikit-learn, pandas, NumPy, Matplotlib
  • Tools and engineering: Git, Jupyter, REST APIs, Linux basics
  • Concepts: data cleaning, feature engineering, model evaluation, exploratory data analysis

And here is the same candidate targeting general software engineering roles:

Skills

  • Languages: Python, JavaScript, SQL
  • Web and backend: Node.js, Express, REST APIs, HTML, CSS
  • Tools: Git, GitHub, VS Code, Postman
  • Concepts: data structures, algorithms, unit testing, agile teamwork

Notice what both versions share:

  • four short labeled groups, not one wall of words
  • roughly 10 to 16 skills total
  • every item could be defended in a technical interview
  • no soft skills, no ratings, no skill bars

Same candidate, same real inventory, two different pages. That is what tailoring looks like.

How to build your skills section step by step

Step 1: Collect your real inventory

Open a blank document and write down every technical thing you have actually used:

  • languages you have written real code in
  • libraries and frameworks from projects or coursework
  • tools you used in labs, internships, clubs, or hackathons
  • concepts you can explain out loud, like recursion or normalization

Be generous at this stage. You will filter later.

Step 2: Pull keywords from 5 to 10 real job descriptions

Find current postings for the exact role you want. For each one, mark:

  • skills listed under requirements
  • skills listed under nice-to-have
  • the exact phrasing used, for example scikit-learn versus sklearn

Make a frequency list. A tool that appears in seven out of ten postings belongs on your resume if you genuinely know it.

Step 3: Intersect, then cut hard

Keep only the skills that are in both lists: things you can defend and things employers ask for.

Then cut to about 10 to 16 items. If a skill was used once in a tutorial two years ago and you could not answer a follow-up question about it, remove it. A short, true list beats a long, shaky one.

Step 4: Group the survivors into labeled categories

Three to five groups work best. Common patterns for entry-level tech resumes:

  • Languages
  • Libraries and frameworks, or Machine learning and data
  • Tools and platforms
  • Concepts or methods

Put the group the job cares about most first. For a data role, that is usually the data stack. For a web role, that is the web stack.

Step 5: Match the employer's exact wording

ATS matching is often literal. If the posting says PostgreSQL, do not write Postgres. If it says Amazon Web Services (AWS), include that form, not just cloud.

Mirror the job description truthfully. Never add a keyword you cannot support, because the interview will check.

Step 6: Pay off every skill elsewhere on the page

For each surviving skill, check that a project bullet, coursework line, or experience bullet shows it in use. If nothing supports it, either add evidence or cut the skill.

Weak vs strong: the same candidate, rewritten

Weak version:

  • Python, Java, C++, JavaScript, SQL, HTML, CSS, React, Angular, Vue, Node, Django, Flask, TensorFlow, PyTorch, Keras, Hadoop, Spark, AWS, Azure, GCP, Docker, Kubernetes, Git, Linux, hard-working, team player

Strong version:

  • Languages: Python, SQL, JavaScript
  • Machine learning and data: scikit-learn, pandas, NumPy
  • Tools: Git, Jupyter, Docker basics
  • Concepts: data cleaning, model evaluation, exploratory data analysis

The weak version triggers three problems at once. The recruiter does not believe it, the ATS match becomes meaningless because every keyword is diluted, and the first technical screen will find the padding within minutes. The strong version is shorter, fully defensible, and every line points to evidence elsewhere on the resume.

Common mistakes in tech resume skills sections

1. The tool warehouse

Listing 30 tools signals that you have touched everything and mastered nothing. Recruiters read long lists as keyword stuffing, and ATS keyword matches do not help if the interview exposes the padding.

2. Rating scales and skill bars

Python: 4/5 or a filled-in progress bar means nothing. There is no shared scale, and many ATS systems ignore graphics entirely. State the skill and prove it with bullets.

3. Listing soft skills as skills

Hard-working, team player, and fast learner waste the most valuable space on an entry-level resume. Show teamwork through a group project bullet instead.

4. Obsolete or trivial entries

Microsoft Word, typing, and internet research do not belong on a tech resume. Microsoft Excel only earns its place for data analyst roles, paired with something real like pivot tables or VLOOKUP.

5. One generic list for every application

The skills section is the cheapest section to tailor. Ten minutes of reordering and rewording per application does more for your match rate than any other quick edit.

6. Skills with no evidence behind them

If your skills section says Docker but nothing on the page shows you using Docker, an interviewer will ask about it. Be ready, or cut it.

Where to put the skills section on the page

For entry-level tech resumes, place skills near the top, right after the summary. You want the keyword match and the quick credibility read to happen early.

Two placement rules:

  • one column, plain text, no tables or graphics, so the ATS can parse it
  • keep it compact: four to six lines, not a third of the page

Copy-ready skills section templates

Adapt these to your real inventory. Delete anything you cannot defend.

Template 1: entry-level machine learning or data science

  • Languages: Python, SQL, R
  • Machine learning and data: scikit-learn, pandas, NumPy, Matplotlib
  • Tools: Git, Jupyter, Linux basics
  • Concepts: data cleaning, feature engineering, model evaluation, cross-validation

Template 2: entry-level software engineer

  • Languages: Python, JavaScript, Java
  • Web and backend: Node.js, Express, REST APIs, HTML, CSS
  • Tools: Git, GitHub, Docker basics, Postman
  • Concepts: data structures, algorithms, unit testing, version control

Template 3: entry-level data analyst

  • Data tools: SQL, Excel (pivot tables, VLOOKUP), Python
  • Visualization: Tableau, Matplotlib, Power BI basics
  • Tools: Jupyter, Google Sheets, Git
  • Concepts: data cleaning, exploratory data analysis, dashboard design, basic statistics

Template 4: career changer with an adjacent background

  • Languages: Python, SQL
  • Data: pandas, NumPy, basic scikit-learn
  • Tools: Git, Jupyter, Linux basics
  • Transferable: your real domain skill, for example statistical modeling or lab automation
A good skills section is a promise the rest of the resume keeps. Keep the promise small and keep it true.

FAQ

How many skills should I list on a tech resume?

For entry-level roles, about 10 to 16 skills grouped into three to five categories. Fewer, well-supported skills are more convincing than a long list you cannot back up in an interview.

Should I include soft skills in the skills section?

Generally no for tech resumes. Soft skills like communication and teamwork are better shown through project and experience bullets, where they come with evidence instead of empty claims.

Do I need to tailor the skills section for every application?

Yes, at least lightly. Reorder the groups and mirror the exact wording of the job description. The skills section is the fastest section to tailor and has an outsized effect on ATS keyword matching.

Can I list a skill I only used in a tutorial or class?

Only if you can answer basic questions about it in an interview. If your knowledge stops at following along with a video, leave it off or build a small project with it first, then list it.

Should I put proficiency levels next to each skill?

No. Ratings like Python: 4/5 or skill bars have no shared meaning across companies and are often skipped by ATS software. State the skill plainly and prove it with project bullets.
